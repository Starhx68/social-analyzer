# SN 查询与锁定功能设计方案

## 1. 需求概述

根据 `sn.md` 文档，需新增一个 Web 菜单界面（PC 端与移动端适配），提供 SN 码的查询与锁定功能。该功能旨在允许用户在销售或录入前验证 SN 码的可售状态，并进行锁定，同时将相关信息（SN 码、照片）自动回填至订单资料中。

**重要限制**：SN 查询与锁定功能仅适用于 **3C数码类产品**。其他品类（家电、家装、适老化）不需要也不支持此功能。

## 2. 业务流程设计

1. **进入界面**：用户点击菜单“SN查询锁定”。
2. **信息录入**：
   * **订单号 (必填)**：输入关联的订单号（对应 XML 中的 `homa_order_no`）。
   * **SN 码 (必填)**：
     * 支持手动输入。
     * **OCR 识别**：点击拍照/上传图标，调用 OCR 接口识别 SN 码并自动回填。
3. **查询状态**：
   * 点击“查询”按钮。
   * 前端调用后端接口，后端封装 XML 请求 `HG960828` (Action: `query`)。
4. **结果展示**：
   * **不可售/失败**：显示错误信息（如“未查到相关信息”），“锁定SN”按钮置灰不可用。
   * **可售/成功**：显示“可售”状态及描述，显示“锁定SN”按钮（高亮可用）。
5. **锁定 SN**：
   * 用户点击“锁定SN”按钮。
   * 前端调用后端接口，后端封装 XML 请求 `HG960828` (Action: `lock`)。
6. **持久化与反馈**：
   * **锁定成功**：
     * 提示“锁定成功”。
     * **自动保存**：系统自动将当前 SN 码更新至对应订单 (`orders` 表)。
     * **图片保存**：如果是通过 OCR 拍照录入的，系统自动上传该图片并保存为该订单的“SN码照片”资料。
   * **锁定失败**：显示具体的失败原因。

## 3. 详细功能设计

### 3.1 前端界面 (Frontend)

* **路由**: `/sn-check` (PC), `/mobile/sn-check` (Mobile)
* **布局**:
  * **PC 端**: 表单布局，包含订单号输入框、SN 输入框（带相机图标）、查询按钮、结果展示区（Card）、锁定按钮（底部）。
  * **移动端**: 响应式 H5 页面，大号输入框与按钮，适配手机操作。
* **交互**:
  * 输入订单号后，可缓存或自动关联上下文（如果从订单列表跳转）。
  * OCR 识别后，自动填充 SN 输入框，并暂存图片文件用于后续“锁定”时的上传。

### 3.2 后端接口 (Backend)

新增 `SnController` 和 `SnService`，提供以下接口：

#### A. SN 查询接口

* **URL**: `POST /api/sn/query`
* **参数**: `{ orderNo: string, sn: string }`
* **逻辑**:
  1. **前置验证**：检查订单的 `plate_type` 是否为 '3C数码'。如果不是，返回错误提示。
  2. 构造 XML 调用 `ExternalInterfaceService.call('HG960828', { Action: 'query', sn, homa_order_no: orderNo })`。
  3. 解析返回 XML。
  4. 返回 JSON: `{ success: boolean, sellState: string, message: string, data: object }`。

#### B. SN 锁定接口

* **URL**: `POST /api/sn/lock`
* **参数**: `{ orderNo: string, sn: string, imageFile: File (optional) }`
* **逻辑**:
  1. **前置验证**：检查订单的 `plate_type` 是否为 '3C数码'。如果不是，返回错误提示。
  2. **前置检查**: 确认订单是否存在。
  3. **调用锁定**: 构造 XML 调用 `ExternalInterfaceService.call('HG960828', { Action: 'lock', sn, homa_order_no: orderNo })`。
  3. **处理结果**:
     * 如果锁定成功 (`success=1`)：
       * **更新订单 SN**: `UPDATE orders SET sn_code = ? WHERE order_no = ?`。
       * **处理图片**: 如果请求包含图片文件，执行文件上传逻辑，并将图片路径保存到订单的资料字段（如 `sn_image` 或对应附件表）。
       * **记录日志**: 记录操作人与时间。
  4. 返回结果与提示信息。

### 3.3 数据库变更

* 检查 `orders` 表是否已有 `sn_code` 和 `sn_image_path` 字段（现有逻辑似乎已有，需确认）。
* 如果需要支持“SN 锁定”状态的本地记录，可能需要在 `orders` 表增加 `sn_locked` (boolean) 字段，防止重复修改。

## 4. 外部接口定义 (HG960828)

* **FunctionID**: `HG960828`
* **Actions**: `query`, `lock`
* **Parameters**: `sn`, `homa_order_no`
* **Addition XML**: 复用现有系统的 `row1` 上下文 (User, IP, etc.)。

## 5. 待确认事项

1. **订单号来源**：界面上是否必须手动输入订单号？是否支持从"订单列表"跳转并自动带入？
   * *建议*：支持手动输入，同时在订单详情页/列表页增加"SN核验"入口，自动带入订单号。
2. **图片保存逻辑**：如果没有使用 OCR（手动输入 SN），是否需要强制用户上传 SN 照片？
   * *建议*：根据现有规则，如果 OCR 图片存在则保存；如果手动输入，建议界面提供"补充照片"选项，或者遵循原有订单审核规则（SN 照片是否必填）。
3. **覆盖规则**：如果订单已有 SN 码，新的锁定操作是否直接覆盖旧数据？
   * *建议*：允许覆盖，但记录日志。
4. **产品类型限制**：已确认 SN 查询和锁定功能仅适用于 **3C数码类** 产品。
   * *实现状态*：✅ 已在接口中添加 `plate_type === '3C数码'` 的验证逻辑。
