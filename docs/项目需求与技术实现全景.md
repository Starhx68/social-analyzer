## 一、项目概述

### 1.1 项目简介

国补订单资料上传系统是湖南省以旧换新活动的订单资料采集平台，支持PC端和小程序双端协同工作。

### 1.2 核心目标

- 从第三方Oracle系统同步订单数据
- 提供订单资料上传功能（发票、SN码、送货单等）
- 实现SN码OCR自动识别
- 将订单数据上报到国补审核系统和中央平台
- 提供订单审核管理功能

### 1.3 技术架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                        前端层                                │
├─────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
```

**已实现功能**:

## 六、关键技术决策

### 6.1 数据同步架构

**决策**: 采用三层表结构 (od_order_subsidy_sync → order_sync → orders)

**理由**:

- 保留Oracle原始数据，便于溯源
- 职责分离，解析数据和业务操作分开
- 查询性能优化，order_sync表有业务索引
- 扩展性强，可对接多个第三方系统

### 6.2 订单唯一同步键

**决策**: 使用 `external_order_id` (Oracle ORDER_NO) 作为唯一同步键

**理由**:

- ORDER_NO是Oracle系统的真实订单号，具有唯一性
- mchnt_ord_no可能为空或不唯一
- 避免重复同步问题

**历史记录**: 2026-01-29决定废弃mchnt_ord_no作为主键

### 6.3 版块类型映射

**决策**: 锁定版块映射关系

**映射规则**:

- jz → 家装 (home_decoration)
- jd → 家电 (home_appliance)
- sj → 3C数码 (digital_3c)
- sl / slh → 适老化 (aging_adaptation)

**历史记录**: 2026-01-29确定并锁定

### 6.4 订单金额字段映射

**决策**:

- 商品价格 (`product_price`) 映射自 `ORDER_ACTINCM_AMT`
- 订单实付金额 (`product_total_amount`) 映射自 `BUYERPAYAMOUNT` (需除以100)
- 所有金额字段保留2位小数

**历史记录**: 2026-01-29更新

### 6.5 权限控制

**决策**: 特权账号拥有查看所有订单数据的权限

**实现**:

- 用户表添加 `is_privileged_organization` 字段
- 中间件 `requirePrivilegedOrg` 检查特权
- RLS策略豁免特权账号

**历史记录**: 2026-01-29优化

## 十一、常见问题

### 11.1 Docker服务无法启动

```bash
# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs [service-name]
```

### 11.2 数据库连接失败

```bash
# 检查PostgreSQL容器状态
docker-compose ps postgres

# 进入PostgreSQL容器
docker-compose exec postgres psql -U postgres -d guobu
```

### 11.3 订单同步失败

**排查步骤**:

1. 检查 `od_order_subsidy_sync` 表是否有数据
2. 检查 `order_sync` 表的 `sync_status` 字段
3. 查看日志中的 `sync_error` 字段
4. 检查数据映射是否正确
